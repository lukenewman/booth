# Booth Backups Implementation Plan (step 5, BOO-103)

> Executed inline overnight on Luke's standing instruction (keep going on the migration project, trust judgement, stop only for his calls). Compact: the executor is the author.

**Goal:** Booth backs the library up to a folder the user picks (external drive, NAS mount, a cloud-synced folder), records what each backup holds, and nudges: "You haven't backed up in X days. Y releases aren't in the last backup. Back up now."

**Spec:** `docs/superpowers/specs/2026-11-02-migration-and-sources-design.md`, section 6 and build step 5. Linear: BOO-103.

## Decisions (mine, for Luke)

- **What's backed up: every present library file** (in place or Booth's), plus a database snapshot. The spec names "the owned folder and the kept originals"; today almost nothing is owned yet, and step 6 is gated on "a real backup of Luke's library exists", so the files read in place are what need protecting now.
- **Layout mirrors absolute paths** under `<destination>/Booth Backup/files/…`, database snapshots under `…/database/` (newest 10 kept). Readable without Booth; a moved file is copied again rather than tracked (simple, and moves are rare).
- **A copy is verified before it counts**: same size, and the same audio fingerprint as the original when Booth has one (byte hash otherwise). Written to a temporary name and renamed into place, so an interrupted copy never looks complete.
- **Incremental and resumable**: a file whose size and modified time match what the backup recorded, and whose copy is still there at that size, is skipped. Nothing is ever deleted from a backup.
- **One destination for now**, stored in the database so more (and other kinds, like a cloud bucket) can be added; the setup refuses a folder inside the library or Booth's data, and warns when it's on the same disk as the music ("won't help if this disk fails").
- **Space checked first**: refuses to start when the destination can't hold what's still to copy.
- **The nudge** appears in the library view when there's no backup yet, the last one is over 7 days old, or releases aren't in it; dismissible for a day.
- **Restore test, first cut**: the database snapshot is integrity-checked after writing. Rebuild-from-tags comes with step 6, when tags carry the meaning.
- **Not run on Luke's real library by me.** Choosing the drive and starting the first 50 GB copy is his click.

## Tasks

1. **Schema + destination.** Migration `021_backups.sql`: `backup_destination(id, kind CHECK 'folder', path UNIQUE, added_at)`, `backup_run(id, destination_id, started_at, finished_at, state CHECK running|done|failed|stopped, files_total, files_done, bytes_total, bytes_done, error)`, `backup_item(destination_id, file_id, fingerprint, size, mtime_ms, dest_path, backed_at, PRIMARY KEY(destination_id, file_id))`. `src/lib/server/backup/library.ts`: `setDestination(db, path, roots)` with checks (exists, writable, not inside library/booth roots; `sameDisk` flag), `getDestination(db)`.
2. **The run.** `runLibraryBackup(db, deps, { onProgress, shouldStop })`: plan (library files to copy vs already held), space check, copy → verify → record per file, database snapshot + integrity check, run row kept current. `deps` injects fingerprint and the database snapshot so the verify script runs on temp dirs. *Tests* `scripts/verify-library-backup.ts`: first run copies and records every file; second run copies nothing; a retagged (changed) file is copied again; a corrupted copy (different bytes at the destination) is detected and re-copied; an interrupted copy leaves no file under the final name; not enough space refuses before copying; a destination inside the library is refused; stop mid-run leaves a resumable state.
3. **Status and nudge query.** `backupStatus(db)`: destination, last finished run, days since, releases with a present file not held at its current size/mtime, files/bytes still to copy, current run progress. *Tests:* release counts before/after a backup and after a change.
4. **API + UI.** `GET/POST /api/backup` (status / set destination), `POST /api/backup/run` (start, background, one at a time), `POST /api/backup/stop`. `BackupPanel.svelte` in Sources → Local (destination, same-disk warning, Back up now, progress, last result). `BackupNudge.svelte` banner in the library view. *Verify:* `bun check`, copy server with a scratch destination and headless Chrome.

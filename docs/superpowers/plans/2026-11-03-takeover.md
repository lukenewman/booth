# Takeover, the Sample and Undo Implementation Plan (step 6a, BOO-102)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Compact like the step 2–5 plans: the executor is the author, so tasks carry decisions, interfaces and test cases rather than finished code.

**Goal:** Booth can take over a release — copy its files into Booth's own folder with everything Booth knows written into their tags, verified, and switch the release's tracks to those copies — starting with a ~10-release sample, and undo it per release while the originals exist.

**Architecture:** A copy is an ordinary file-list row owned by Booth that says which original it replaced. Sync, findings, rekordbox and backups all learn one rule: *a file with a copy is superseded by it*, so the track keeps its id and everything on it while pointing at the copy. A background runner (like the backup runner) works release by release; a release flips only when every file succeeded.

**Tech Stack:** SvelteKit + Bun, bun:sqlite, taglib-wasm (the existing safe tag writer), ffmpeg fingerprints.

**Spec:** `docs/superpowers/specs/2026-11-02-migration-and-sources-design.md`, sections 3–4 and build step 6.

## Scope: step 6 split in two

- **6a (this plan):** the settings fix the takeover needs, Booth's folder location, the takeover engine, sync/findings/rekordbox/backup integration, the sample, undo, the rebuild-from-tags check.
- **6b (next plan):** renames on owned releases (BOO-100), writing edits into owned files (stars, notes, batched), the drop folder writing tags (BOO-77), names of owned files read from their tags.

6a changes no file outside Booth's folder, and none of Luke's originals ever.

## Global Constraints

- "The original is never touched." No write, move or delete of any file outside Booth's folder, ever, in this plan.
- "A release flips only when every one of its files succeeds; otherwise it stays in place and a finding says why."
- "Fingerprint the copy; refuse it if the audio differs from the original."
- "That location is fixed from then on; later tag changes never move the file."
- "Undo is per release, for as long as that release's originals exist." "Stars, notes and crates survive."
- "It says plainly that other apps won't see changes to these releases until they are cut over."
- Never bulk-delete real data; verification runs on `sqlite3 .backup` copies and temp dirs; Luke starts the first real takeover himself.

## Decisions (mine, for Luke)

- **Settings stop living in `.env` under `bun dev`.** Writing `.env` restarts the dev server (that's what broke it when rekordbox was connected), and choosing Booth's folder writes a setting mid-takeover. Dev writes to a git-ignored `.booth-settings.env` in the repo, loaded at server start on top of `.env`. The desktop app is unchanged.
- **Booth's folder: chosen at the first takeover**, defaulting to `~/Music/Booth`, with the folder chooser. Refused inside Music.app's media folder, a folder source or a backup destination. Today's hidden `~/.booth/library` is empty on Luke's machine, so changing the location is refused while the current folder holds files (moving them is a later job, noted in the UI copy).
- **What goes into a copy's tags:** the names Booth shows (title, artist, album, album artist, year, track number), plus the existing Booth fields (date added and its provenance, starred, vetted, Discogs release, note as comment, tempo, fingerprint). Names are written so that 6b can read owned files' names from their tags without any visible change.
- **WAV and other untaggable files are copied verbatim** (byte-identical, sha256-checked), and their Booth facts stay in the database. The sample screen says so for any WAV it picks. rekordbox's grids and cues are not written into tags in 6a; they stay rekordbox's, re-imported each sync.
- **Track names still come from Music.app in 6a**; only the file a track points at changes. 6b switches owned files to their own tags.
- **A copy whose file goes missing raises a normal missing finding**; Booth never silently falls back to the original.
- **Originals of taken-over releases stay in the backups** (they are the undo path and, until cutover, Music.app's and rekordbox's live files). Copies are backed up under the "Booth" place.
- **The takeover writes real new files** (tags change the bytes), so its space check needs the real size, not the clone-sharing kind.
- **Undo deletes only the copies Booth made**, after checking the original is still there with the same audio; it refuses otherwise.

## Review Focus

1. A sync after a takeover changes nothing visible: the same tracks (same ids), the same stars, notes, playlists and gig rows, no duplicate finding for original + copy, and rekordbox's facts still attached.
2. A release with one failing file (unreadable, audio mismatch, disk full mid-release) leaves no copies behind and no track pointing at a copy.
3. Stop, a server restart or a crash mid-release: on resume nothing is half-flipped and no orphan copy is counted as done.
4. Undo after the original vanished (deleted, drive unplugged): refused, nothing deleted.
5. The same file taken over twice (two releases sharing a file, or a re-run): one copy, not two.

### Task 4: The takeover engine

**Files:** Create `src/lib/server/takeover/engine.ts`. Modify `tag_schema.ts` (names in `BoothTrackFacts` → standard tags), `tag_writer.ts` only if names need a second pass. Reuse `ingestTargetPath`, `dedupePath`, `writeTags`.

**Interfaces:**
- `planTakeover(db, releaseIds, { root })` → per release: files `{ fileId, trackId, source, target, size, writable }`, problems (a file missing, already a copy, outside the file list), `bytes`.
- `takeOverRelease(db, deps, releaseId, { root, runId, shouldStop })` → `{ ok: true, files } | { ok: false, reason }`. Per file: target from Booth's names (album artist / album / `NN title`), deduped against disk and this run; writable → `writeTags(source, facts, target)` (fingerprint-checked); else byte copy + sha256 check. Only when every file succeeded, one transaction: insert copy rows (`ownership 'booth'`, `copy_of`, fingerprint, size, mtime), re-point each track's local link to its copy, mark the release done. On any failure: delete this release's new files, record the reason, raise a `takeover` finding. A stop request is honoured between releases, never mid-release.
- `deps`: `{ writeTags, fingerprint, freeBytes, copyFile? }`, so tests run on temp dirs without ffmpeg.

- [ ] Tests (fake deps, temp dirs): a two-track release is copied, tagged (facts and names round-trip through `readTags`), flipped; the originals' bytes and mtimes are unchanged; a sync afterwards changes nothing (Review Focus 1); one file whose "audio" differs after writing → nothing flipped, no new files left, a `takeover` finding (2); a crash simulated after copying but before the flip → the next run treats the release as pending and leaves no orphan (3); a WAV is copied verbatim; two releases sharing a file → one copy (5); not enough space → refused before copying. Watch fail, implement, green, commit.

### Task 5: Undo and the rebuild-from-tags check

**Files:** Create `src/lib/server/takeover/undo.ts`, `src/lib/server/takeover/rebuild.ts`.

**Interfaces:**
- `undoPreview(db, releaseId)` → `{ files, lost: string[] }` (6a: always empty; 6b fills it with renames).
- `undoRelease(db, deps, releaseId)`: every original present with the recorded fingerprint, else refuse naming the file (Review Focus 4); re-point links to the originals; delete the copies (files and rows) — only files whose row says Booth made them; mark `takeover_release` undone.
- `rebuildCheck(db, releaseId, deps)` → `{ matches: boolean, differences: { trackId, field, db, tags }[] }`: reads each copy's tags and compares stars, vetted, note, date added and provenance, Discogs id, tempo and names with the database. Run after each release's flip (a mismatch fails the release before it flips) and on demand.

- [ ] Tests: undo restores the database exactly (snapshot of track, source_link, playlist_entry, gig rows, stars, notes before takeover equals after undo); copies are gone, originals untouched; undo with the original deleted → refused, nothing deleted; `rebuildCheck` matches after takeover and reports a difference when a copy's tag is altered. Watch fail, implement, green, commit.
